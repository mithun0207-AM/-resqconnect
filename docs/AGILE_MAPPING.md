# ResQConnect implementation mapped to Agile / Scrum

- Product goal: enable authenticated community members to share and coordinate non-emergency community support requests.
- Sprint 1: UI shell, Supabase project, schema, auth and profile setup.
- Sprint 2: create/read reports, input validation, RLS and incident board.
- Sprint 3: realtime subscriptions, status workflow and volunteer profiles.
- Sprint 4: usability tests, accessibility, abuse reporting, moderation, privacy review and deployment.
- Product backlog examples: report categories; admin moderation queue; volunteer verification; abuse reporting; email notifications; location privacy controls; audit trail; data deletion.
- Definition of Done: feature tested with two accounts, RLS reviewed, error states handled, mobile layout checked, and documentation updated.
